# Getting Down to Brass Tacks: The SLA Lowdown

1. Purpose

1.1 This guide explains how the Service Desk handles tickets.

1.1.1 Scope

1.1.1.1 The guide covers tickets raised by email, phone, and the portal.

1.1.1.2 It does not cover security incidents, which go to the Security team.

2. Handling a ticket

Follow these steps when a ticket arrives:

1. Read the ticket.
2. Check the requester's account in the CRM.
3. Set the category.
4. Set the priority using the P-matrix.
5. Assign the ticket to yourself.
6. Send the acknowledgement template.
7. Check the knowledge base for a known fix.
8. Apply the fix if there is one.
9. If there is no fix, escalate to second line.
10. Record the time spent.
11. Update the requester.
12. Close the ticket when the requester confirms.
13. If the requester does not reply within 5 working days, close the ticket and send the closure template.
14. Run the weekly ticket report on Fridays.

3. Priorities

- Priority 1
  - Whole office cannot work
    - Examples
      - Email down for everyone
      - Network outage
  - Respond within 15 minutes
- Priority 2
  - One team cannot work. Respond within 1 hour. A P2 can be upgraded to P1 if the problem spreads to more than one team or if a director is affected, but only after the shift lead agrees, and the upgrade must be recorded in the ticket's history with the reason, the time, and the name of the shift lead who agreed to it, so that the monthly SLA report can account for upgraded tickets separately from tickets that were P1 from the start.
- Priority 3
  i. One person cannot work.
  ii. Respond within 4 hours.
     a) Unless the person is on leave.
     b) Then respond within 1 working day.

4. Need help?

Ask your shift lead.
