# Tables and figures

Apply this branch when a table, figure, or chart is present. For a display's marks, layout, and
building code, also use the [charts skill](../../charts/SKILL.md).

For an accessible analytical table, consult the UK Analysis Function table guidance
(`AUTH-UKAF-DATA-TABLES` in [source provenance](source-manifest.md)) only for a choice that the
rules below do not settle. When the output explicitly selects IBCS notation, apply [IBCS
notation](ibcs-notation.md) to the display's text.

- **Data tables.** Use a data table only when row-and-column relationships carry meaning. Use a
  list for a sequence or one-dimensional set. Use the output format's layout and spacing controls
  for presentation.
- **Tables used for layout.** Do not use a table for page or code layout. Do not divide a
  one-dimensional list between table columns.
- **Procedures and tables.** Keep the primary numbered procedure outside tables. Do not put a table
  inside a numbered procedure. Do not hide a procedural step in a table cell.
- **Merged cells.** Do not merge cells. Split a complex table when distinct rows and columns cannot
  express its relationships.
- **Table captions and header cells.** Associate each caption with its table through the output
  format's structural markup. Associate every data cell with each header cell needed for
  interpretation.
- **Row headers.** Put each row's identifying header in the first logical column. Follow the
  document's text direction.
- **Table headers.** Write concise, specific headers without ellipses. Keep each header meaningful
  without completing its sentence in a data cell. Preserve or repeat headers across page breaks
  and scrolling regions.
- **Cell syntax.** Use parallel fragments or sentences within each column. Apply one punctuation
  pattern to comparable cells.
- **Limit table columns.** Keep only columns needed for the table's purpose. Split a table only when
  every resulting relationship remains clear.
- **Reflow data tables.** Keep each data cell readable during reflow. Contain necessary
  two-dimensional scrolling within the data table.
- **Typical table problems.** Reject a table with poor distribution, unbalanced dimensions, or
  rambling prose in cells. Prefer relatively uniform data distribution across two dimensions or
  many parallel items with distinct attributes.
- **Editing table content.** Edit the table for style. Check internal consistency, consistency
  across multiple tables, and consistency with the surrounding text. Recompute every total and
  subtotal. Check abbreviations, precision, note references, notes, and sources. Check the table's
  relevance to the text and compare it with other tables for redundancy. Make every number range
  explicit, without gaps or overlaps.
  Read it as a lay reader or non-technical editor and confirm that it makes logical sense.
- **Numeric table alignment.** Right-align quantitative columns. Align comparable decimal values on the decimal marker when practical. Use the right edge when values lack a common marker or a column includes non-numeric statuses.
- **Values in prose and tables.** Narrate a result. Put a series or inventory of exact values in a
  table. Keep an individual value in prose when it carries the sentence's point.
- **Display purpose.** Give every figure and table one job. State that job in its heading, caption,
  or introduction.
- **Figure titles and captions.** Give each figure a concise title or caption in sentence case.
  Prefer a complete sentence for a caption, and always end a caption with punctuation. Leave a
  standalone title or fragmentary note without terminal punctuation. Follow the governing format
  when it requires another case, title form, or punctuation.
- **Figure references.** Refer to each numbered figure in the text. Use one reference form for one
  purpose throughout the document. Preserve governing numbering and cross-reference syntax.
- **Figure callouts.** Use a callout for a short label that points to something within a figure.
  Keep it brief and use sentence case. End a complete sentence with a full stop. Leave a fragment
  without ending punctuation. Preserve governed label punctuation.
- **Introductory sentences.** Add a complete-sentence introduction before a table or figure when its
  heading, caption, and content do not make its purpose or context clear. Summarise its message in
  prose when readers need help interpreting it, without duplicating the display's details.
- **Table titles.** Use concise, explanatory sentence-case wording for a table's heading, title, or
  caption.
  Identify any measure, scope, geography, or period that the table body and surrounding heading do
  not make clear. Follow the governing format when it requires another convention.
- **Table notes.** Put information that applies to the whole table in its title or an adjacent note.
  Qualify an individual cell with a consistent footnote reference. Follow the governing format's
  note and marker conventions.
- **Blank data cells.** Do not leave a data cell blank when the absence has meaning. Use `0` only for a true zero. Otherwise, write an explicit status in the document language, such as *No data* or *Not applicable*. Follow a selected style module's empty-cell convention, such as [APA tables and figures](apa-style.md#tables-and-figures).
- **Table units.** Put a shared measurement unit in the column or row header. Put a table-wide unit
  in the table title. Follow a selected style module when it places table-wide units elsewhere,
  such as the general note under [APA tables and figures](apa-style.md#tables-and-figures).
- **Chart titles.** Write an explanatory chart title as a testable main message supported by the displayed data. Use a subtitle to identify any measure, scope, or period that the title and chart do not make clear. When the governing format fixes the figure elements, as APA Style does, give that information in the title, axis titles, or note instead of a subtitle. Use a neutral topic title for exploratory charts.
- **Data-display sources.** Give each data table and chart an adjacent source block that names and links the exact dataset or publication. Name every source used. Put material caveats and the data date or version in that block. Link the exact source rather than an organisation homepage. When a citation style governs, attribute sources in the form and position that style requires.
- **Reused display credits.** Apply [Rights, permissions, and credit
  lines](references-and-citations.md#rights-permissions-and-credit-lines) to the credit line, its
  placement, and the permissions record for each reused or adapted visual or table.
- **Chart text alternatives.** For a chart's short text alternative, identify the chart type and key message. Put relationships, trends, material exceptions, and exact values that matter in a long description or accessible data table. Include only points that carry the message.
- **Stand-alone displays.** For a table or figure intended for independent reading, confirm that its
  title, headers, units, symbols, notes, and source supply the context needed without surrounding
  prose. Define every non-standard abbreviation and symbol in that display's title, body, legend,
  or note. Repeat the definition even when it appears elsewhere in the document.

Complete this branch when each display has one stated purpose, usable structure, and checked
content. Include source or credit information and an accessible text alternative when the
applicable rules require them.
