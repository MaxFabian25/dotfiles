# How a REF is read: what changed and what showed it

The [skill](../SKILL.md) says how a `REF` reads now. This file keeps what the releases of 12 and 13 November 2026 changed for callers, and the cases through real Excel and on stand-ins that showed it.

`errors` and a read's `address` name a sheet as Excel does, in single quotes with each apostrophe in its name doubled, so an `errors` entry such as `'It''s'!B2` and a read's `address` such as `'It''s'!$B$2` are each a `REF` that reads back, and `--set` takes a cell named that way. On 12 November 2026 the `quoted` cases of `test_fixtures.py` took `'It''s'!B2` from the `errors` of a job through real Excel, read it back, set a cell on that sheet, and read back the `address` that read gave, `'It''s'!$B$2`. On the script as released before, every one of those reads and the set failed with `Exception from HRESULT: 0x800A03EC`, because that script took no apostrophe inside a quoted sheet name and looked such a `REF` up as a workbook name. A read through a workbook name that points at such a sheet gave its `address` with the apostrophe single on that script, which no `REF` accepted: one `excel.py` job that day on the case's workbook gave `'It's'!$C$3` for its name `Tripled`, where the `quoted` case gets `'It''s'!$C$3`.

A `REF` that opens with a quote and is no quoted sheet name with a range after it is refused, as `'It's'!B2` is, with its single apostrophe inside the quotes. The read fails with `'It's'!B2 is no sheet name in single quotes with a range after it: double each apostrophe inside the quotes, as in 'It''s'!B2`, and a `--set` on such a `REF` ends the job with that error, without saving. `'It's'` is not taken for the sheet `It's`, because `'It''s'` would then name two sheets. The `quoted` cases showed the refused read and the refused set through real Excel on 12 November 2026, where the released script had failed the read of `'It's'!B2` with `0x800A03EC` and no hint, and `scripts/test-read-guard.ps1` showed the reads, the addresses and the refusals on a stand-in workbook with no Excel that day (`quoted`). Its stand-in sheet with a letter outside A to Z in its name read in quotes that day, and on 13 November 2026 without them too, while an unquoted sheet name with a space or a hyphen was taken for a workbook name, which fails as a missing name does. A `REF` whose quoted sheet name ended early, at an apostrophe before a `!`, as in `'A'!B'C'!D1`, is refused in that case too, and its table columns `'My sheet'!T[Owner''s share]` and `S!T['#Items]`, which hold an apostrophe elsewhere in the range, reach their sheets. No test reads a table column through real Excel.

A sheet name with a letter outside A to Z needs no quotes, and a sheet name can hold `=`. On 13 November 2026 the `letters` case of `test_fixtures.py` read `Økonomi!A1` through real Excel with the same result as `'Økonomi'!A1`, read a workbook name with such a letter, and set a cell with the `REF` `'a=b'!$A$1`, which is the `address` a read gives for a cell on a sheet named `a=b`. On the scripts as released before, the same case failed the read of `Økonomi!A1` with `Exception from HRESULT: 0x800A03EC` and no hint, because the job took an unquoted sheet name of the letters A to Z only and looked the `REF` up as a name, and its set ended the job with the hint to double an apostrophe, because `excel.py` cut `REF=VALUE` at its first `=`, into the `REF` `'a`. The cut of `--set` is also tested without Excel, by the check of `test_fixtures.py --no-excel` that begins `--set REF=VALUE is cut`, and the `mixed-formula` case showed through real Excel that day that `--set REF==0.1` still writes the formula `=0.1`. That check also shows the cut's limit: a table column whose name holds `=`, as in `S!T[a=b]=5`, cannot be set by that name, because the cut falls inside the name. A read gives no `address` of that form. `scripts/test-read-guard.ps1` showed that day that unquoted stand-in sheet names with a digit and an underscore, and with an accent written as a combining mark, reach their sheets.

Whether the sheet or the name lookup is asked first depends on how the `REF` writes its sheet, so that every `REF` reads what it read before 13 November 2026. With the sheet name in quotes, or unquoted in A to Z, digits and underscores, the sheet alone is asked, as before. PowerShell's match ignores case, which takes the dotted capital `İ` (U+0130) and the Kelvin sign (U+212A) for `i` and `k`, so a sheet name with those and no other letter outside A to Z is asked alone too, on the released script as now, as a probe on stand-in workbooks showed on 13 November 2026. A `REF` whose unquoted sheet name holds any other letter is first looked up as a name, which is all the released script did with it, and asked of the sheet when the workbook has no such name. The lookup finds a name scoped to that sheet wherever its cells lie. So `Økonomi!FY2024` reads a name `FY2024` scoped to the sheet `Økonomi`, which a file from another tool can hold, and `'Økonomi'!FY2024` reads the cell `FY2024`. One `excel.py` job on each pair of scripts on 13 November 2026 read 43 references on a synthetic workbook, among them a workbook name, names scoped to a sheet with their cells on that sheet and on another, such names spelt as a cell's address, a name made with `OFFSET` and an intersection. Each of the 24 that read on the released scripts read the same on the changed ones, apart from the 5 of several rectangles, which now fail. Three that failed on the released scripts read now: `Økonomi!A1`, `Økonomi!FY2024:FY2025`, and `Økonomi!Beløb`, which asks the sheet for the workbook name `Beløb` that points at it. A name scoped to a sheet whose cells lie on another sheet still fails with `Exception from HRESULT: 0x800A03EC` where its sheet is named in quotes or in A to Z, as `S!Away` did in both jobs. `scripts/test-read-guard.ps1` showed both orders on a stand-in workbook that day, and that the name lookup is asked for no `REF` whose sheet is named in quotes or in A to Z.

Since a later release that day the read goes on to the sheet only when the lookup fails with `0x800A03EC`, which `Names.Item` gave in a probe in real Excel on 13 November 2026 for all nine missing names it was asked, such as `Økonomi!A1` and `Øl!A1` on a sheet the workbook lacks, and an `excel.py` job that day read an intersection, table columns and a spilled range behind `Økonomi!` the same on the scripts before and after. Any other error ends the read: in `scripts/test-read-guard.ps1` that day, stand-in lookups that a busy Excel refused or that failed with `0x800AC472`, `0x800706BA`, `0x80010105` or no COM error failed it, where the script before read the cell `'Økonomi'!$FY$2024` for `Økonomi!FY2024` after all but the refusal. Excel gives `0x800A03EC`, with no text, for many other failures too, so a lookup that fails with it for another reason still goes on to the sheet. The `letters` case of `test_fixtures.py` read through real Excel that day `Økonomi!Elsewhere`, scoped to that sheet with its cell on `S`, as `'S'!$A$1`, and `Økonomi!FY2024` as the name's cell `'Økonomi'!$B$1`. Before, no case read a sheet-scoped name through real Excel, and a planted defect that skipped the lookup failed only checks on stand-ins. The job of 43 references read and failed the same on the scripts before and after, apart from the counts in the errors of `Pairs` and `Long8`.

Read one cell or rectangle with each `REF`, and copy one cell or rectangle of an `errors` entry at a time. A read of several rectangles, typed as in `S!A1:A2,C1:C2` or reached through a name, fails with `range has 2 rectangles; read each rectangle by its own REF`, because Excel gives the values of the first rectangle only, under the address of them all. It fails the job as any failed read does. On 13 November 2026 the `areas` case of `test_fixtures.py` got that error through real Excel for `S!A1:A2,C1:C2`, for `S!A1,C1:C2` and for a workbook name of two rectangles, and read `S!A1:A2` and `S!C1:C2` by their own `REF` in the same job. On the script as released before, that case read `S!A1:A2,C1:C2` and the name as the two values of `A1:A2` under the `address` of both rectangles, with no sign that two were missing, and failed `S!A1,C1:C2`, whose first rectangle is one cell, with `Excel gave no answer for the values`. `--set` on several rectangles ends the job with `set target S!A1:A2,C1:C2 is not one cell`, as it did before (`areas-set`). `scripts/test-read-guard.ps1` showed the error that day on stand-in ranges of two rectangles, with no Excel (`two_areas`, `one_cell_first`).

For a name that lists many rectangles, Excel gives a shorter range or none, with no error. In a probe in real Excel on 12 November 2026 a name of 40 rectangles gave a range of 17, two names of 8 rectangles on a sheet with a long name gave 5 and 4, and a name of 150 single cells gave no range. Neither did a name that refers to no cells, such as the constant `=5`, nor a name of two rectangles on two sheets. The job handles them as follows:

- Since 13 November 2026 the job also asks for the text of each name it reads or sets through, which Excel gives whole, at one more call per name, and counts the references it lists: one more than its commas outside quotes, brackets and parentheses. A read fails when the text lists more rectangles than the range has, with the text's count, and a `--set` ends with `set target … is not one cell`, also where Excel gave one cell. That day the `areas` case of `test_fixtures.py` got `range has 40 rectangles` through real Excel for its name of 40, where the script before said 17, and `scripts/test-read-guard.ps1` showed the rest on stand-ins (`cut_to_one`, `cut_short`, `sets`, the comma cases, and `no_text`, for which a refused text fails the read). A probe in real Excel that day kept rectangles that touch or repeat separate in the range. The count gave 8 for `Far8` and 40 for `Økonomi!LongAway`, of 40 rectangles on `S`, in one `excel.py` job that day, where the script before said 4 and 17. `AREAS(name)` is not used, because it takes a name spelt as a cell's address, as `Far8` is, for that cell, nor the sheet's `Range`, which fails for a name whose cells lie on another sheet.
- A name with no range fails its read with `Excel gave no range for the name Singles, whose text has 1297 characters: it has none for a name that refers to no cells, to cells on several sheets, or to more rectangles than it gives as one range, so give each rectangle as a REF of its own`, and a `--set` through such a name ends the job with that error, where the released script said `set target Fixed is not one cell` (`no-range-set`, 13 November 2026). The error is for a name asked for by itself or found by the name lookup: in the job of 43 references on the changed scripts, `Økonomi!LocalConst`, a constant scoped to that sheet, got it, where the released script said `Excel gave no answer for the range`, while `'Økonomi'!LocalConst` and `S!SConst`, which are asked of the sheet, failed with `Exception from HRESULT: 0x800A03EC` on both pairs of scripts. The released script reported the name of 150 cells and the constant of the `areas` case as `Excel gave no answer for the range`, which is what a call that a busy Excel refused gives. The job tells the two apart by asking for the name's text and then for the range again: a name that gives its text and twice no range gets the new error, one that gives neither keeps the old one, and one whose range comes on the second ask reads (`long_name`, `no_range` and `late_range` in `scripts/test-read-guard.ps1`, that day). A refused call, an answered text and a second refused call in a row would still get the new error.
- What stays undetected is a name cut down to one rectangle whose text lists one reference, which the count takes as one: another name, a formula's result or a union in parentheses, as in `=(S!$A$1,S!$C$1)`. It would read as that rectangle with `ok` true, and `--set` would write to it where it is one cell. No probe cut a name below four rectangles.
