---
name: excel-com-wsl
description: Open, recalculate, read, change and save an .xlsx in desktop Excel on Windows from WSL, over COM through powershell.exe. Use when a workbook must be checked as Excel itself calculates it, such as one written by openpyxl with no cached values, a model whose results LibreOffice may calculate differently, a check that a named input still drives the result, or a question of whether Excel has to repair the file. Also use before writing or debugging PowerShell that drives Excel's COM objects, or when such a script fails with 0x800A03EC, a cast error or a calculation timeout.

# Excel over COM from WSL

A clean LibreOffice recalculation doesn't show that Excel opens a file without a repair or calculates the same numbers. Desktop Excel on the Windows host is the authority. Drive it over COM from WSL with Windows PowerShell.

## Check a workbook

```sh
python3 -I scripts/excel.py model.xlsx --read Result --read 'Model!B2:B4' --set Growth=0.1 --save baseline.xlsx
```

`REF` is a workbook-scoped name or a `Sheet!A1` range, and names one cell or one rectangle. A sheet name goes in single quotes unless it holds only letters, digits and underscores, as in `'My sheet'!A1`, and each apostrophe in a quoted name is doubled, as in `'It''s'!B2`. The letters can be of any script, with their accents, so `Økonomi!A1` needs no quotes. In a shell script or an agent's shell, put a quoted `REF` in double quotes, as in `--read "'It''s'!B2"`, which one `excel.py` job read through bash on 12 November 2026. An interactive bash takes the `!` in double quotes for a history reference and runs nothing, as a probe in bash 5.2 showed that day. Inside double quotes a shell also takes the `$` of an `address` such as `'It''s'!$B$2` for a variable, so leave each `$` out, because `B2` names the same cell, or write it as `\$`: a probe in bash 5.2 on 13 November 2026 turned `"'a=b'!$A$1=5"` into `'a=b'!=5`. `--set REF=VALUE` takes a number, `true`, `false`, `null` or text, and `--set REF==0.1` writes the formula `=0.1`. The `REF` ends at the first `=`, or at the first `=` after the quoted sheet name it opens with, so `--set "'a=b'!A1=5"` sets `A1` on the sheet `a=b`.

The script copies the workbook and `scripts/excel-job.ps1` into a job folder in the Windows user's temp folder and runs them there. Excel gets a hidden instance of its own, with macros, link updates, events and alerts off. It opens the copy, recording any repair, rebuilds the calculation and reads each `REF`. With `--set` it changes those cells, recalculates and reads again. It saves the copy, reopens it, reads once more and quits, then the script deletes the job folder.

While Excel calculates a large workbook it turns calls away. The job registers a COM message filter, so a call that Excel turns away waits 200 ms and goes again, for up to `--calc-timeout`, and `busy_retries` counts those waits. Without the filter the job ended with `Call was rejected by callee` (`RPC_E_CALL_REJECTED`, 0x80010001), or a read came back as `read_error: You cannot call a method on a null-valued expression`, because PowerShell hands back `$null`, with no error, for a property that a busy Excel refused. On 12 November 2026 the busy case of `test_fixtures.py`, in which a second client keeps the job's Excel rebuilding a workbook of 160,000 formulas, ended with the first error before the filter and passed with 24 waits after it. A probe that day, polling a range on such an Excel 83 times without the filter, got the first error 3 times and the second twice. A call whose wait runs out can still come back as `$null`, so a read checks the answers Excel always gives, such as the cell count, and reports `read_error: Excel gave no answer for …` where the script before recorded an empty value: on 12 November 2026 `scripts/test-read-guard.ps1`, which runs the read on stand-in workbooks with no Excel, got an empty value for four of six refused reads before the check and none after it. A refused error scan ends the job, and the one-line summary counts `read_errors`.

It prints JSON, or writes it to `--json OUT.json` and prints one line:

| Field | Holds |
|---|---|
| `open` | `load` (`normal`, `repair` or `extract data`), `repaired`, `failed_loads`, `external_links` |
| `settings` | calculation mode as opened, iteration, force full calculation |
| `base`, `after`, `reopened.values` | each `REF` at open, after the sets, and after the save and reopen: its `address`, such as `'Model'!$B$4`, and `value`, `text`, `formula`, or `values` for a range |
| `ok` | true when Excel finished the job, every read gave an answer and the error scan could tell for every sheet |
| `errors` | the cells holding an error value that a formula made, by sheet |
| `errors_unscanned` | the sheets whose error cells the scan could not list, each with its `sheet` and the `reason` |
| `error`, `error_line` | why the job failed, and the line of `excel-job.ps1` that stopped it, if one did |
| `busy_retries` | how many times a call waited for a busy Excel |
| `runner` | `timed_out`, and `stopped`, the processes the script tried to stop, each with its outcome |
| `excel` | Excel's `version`, `build`, `os`, `pid`, its Office log `session`, and a `session_reason` when the job found none |
| `office_logs`, `runner.office_logs` | the Office log files of the job's Excel session that the job deleted, or that the script deleted after it stopped that Excel: `session`, `removed`, `bytes`, `left`, and a `reason` when it left any, found none or found no session |
| `timings_ms` | elapsed time at each step |

An error value reads as `{"error": "#DIV/0!"}`. The exit status is 0, with `ok` true, when Excel finished the job, every read gave an answer and the error scan could tell for every sheet. Otherwise it is 1 and `error` says why, so a damaged file exits 1 with its `failed_loads` filled in. `--job-timeout` (300 s) stops only this job's Excel and PowerShell, and `--calc-timeout` (120 s) limits each calculation and each call's wait for a busy Excel, so several long waits can add up to the job's limit. When the job's PowerShell ends without a result, the script stops that job's Excel by its process ID, and `runner.stopped` lists it. A limit that falls while Excel is still starting waits up to 60 s for that process ID, because ending PowerShell first left a hidden Excel running in a fixture run on 12 November 2026.

A read that failed, such as a `REF` the workbook lacks, fails the job. `error` says how many reads failed and names the first, as in `2 of 4 reads failed; the first is NoSuchName at open: …`, where a `REF` that fails at open and after the reopen counts twice. The reads that worked keep their values in `base`, `after` and `reopened.values`, and `--save` still keeps the copy, because Excel finished it. Before 12 November 2026 such a job exited 0 with `ok: true` and showed the failure only in that range's `read_error` and the summary's `read_errors`, so a caller that tolerates a bad reference now has to read the ranges of a failed job. On that day the `unread` case of `test_fixtures.py`, which reads a name the workbook lacks beside one it has, ended `ok: true` on the script as it was, and with status 1, that `error`, the other name's value and the saved copy on the changed one.

A `REF` reads as follows. [references/ref-parsing.md](references/ref-parsing.md) keeps what each release changed for callers and the runs that showed it: read it before you change how `excel-job.ps1` or `excel.py` takes a `REF` apart or looks it up, and when a `REF` fails or reads otherwise than this list says or than an older script read it.

- `errors` entries and a read's `address` name a sheet as Excel does, in single quotes with each apostrophe doubled, as in `'It''s'!$B$2`. A read's `address` reads back as a `REF`, as does each cell or rectangle of an `errors` entry, and `--set` takes such a cell (`quoted` cases of `test_fixtures.py`, 12 November 2026). Copy one cell or rectangle of an `errors` entry at a time, because an entry such as `'Model'!C1,A2:A4` lists several, and a read of several fails (`areas`, 13 November 2026).
- A `REF` that opens with a quote and is no quoted sheet name with a range after it, such as `'It's'!B2`, fails its read with a hint to double each apostrophe, and a `--set` on it ends the job without saving (`quoted`, 12 November 2026).
- A table column whose name holds `=`, as in `S!T[a=b]=5`, cannot be set by that name, because `--set` cuts `REF=VALUE` inside it (the `--no-excel` check `--set REF=VALUE is cut`, 13 November 2026).
- With the sheet in quotes, or unquoted in A to Z, digits and underscores, the sheet alone is asked. An unquoted sheet name with any other letter is first looked up as a name scoped to that sheet, wherever its cells lie, so `Økonomi!FY2024` reads a name `FY2024` scoped to `Økonomi` where the workbook has one, and `'Økonomi'!FY2024` reads the cell (`letters` case, and `scripts/test-read-guard.ps1` for the quoted form, 13 November 2026). The read goes on to the sheet only when that lookup fails with `0x800A03EC`, and a name scoped to a sheet whose cells lie on another sheet fails with `0x800A03EC` where its sheet is in quotes or in A to Z (a probe in real Excel, `scripts/test-read-guard.ps1` and an `excel.py` job of 43 references, 13 November 2026).
- Each `REF` reads one cell or rectangle. Several rectangles, typed or behind a name, fail the read with `range has N rectangles; read each rectangle by its own REF`, where a name's count comes from its text, because Excel cuts the range of a long name short, and `--set` ends with `set target … is not one cell` (`areas`, `areas-set`, 13 November 2026).
- A name with no range, such as a constant or a name over several sheets, fails with `Excel gave no range for the name …` when it is asked for by itself or found by the name lookup, and with `0x800A03EC` when it is asked of a sheet in quotes or in A to Z. `Excel gave no answer for the range` means Excel gave neither the range nor the name's text, as a busy Excel that refuses a call does (`no-range-set`, `no_range` in `scripts/test-read-guard.ps1` and the job of 43 references, 13 November 2026).
- Undetected: a name cut down to one rectangle whose text lists one reference, such as another name, a formula's result or a union in parentheses, reads as that rectangle with `ok` true, and `--set` writes to it where it is one cell. No probe cut a name below four rectangles: in real Excel on 12 November 2026 names of 8 and 40 rectangles came back as 4, 5 and 17.

`errors` lists, by sheet, the cells that hold an error value a formula made: the formula cells, and the cells into which a dynamic array formula in another cell spilled an error. An entry holds one sheet's cells in reading order, as in `'Model'!C1,A2:A4`, with a merged cell given as its first cell and an apostrophe in the sheet's name doubled. Typed-in error values are left out, as they always were, and a sheet whose only error values are typed in is clean.

The scan asks Excel in formulas, which Excel answers on a protected sheet as on any other. `ISERROR(SUM(range))` says in milliseconds whether a range holds an error value, so a sheet with none costs one question. A range that holds one is halved until a piece is small enough for Excel to say of each cell whether it holds an error value and whether it is a formula cell, and `HasSpill` then tells a spilled error from a typed-in one. The questions are in A1 addresses, so the scan puts an Excel that a workbook opened in R1C1 reference style into A1 style and back, and the saved copy keeps R1C1. A sheet goes into `errors_unscanned` with the reason, and fails the job as a failed read does, because `errors` is then not the whole answer, in two cases:

- Excel gave something that is no answer to one of those questions, such as an error value.
- Listing the sheet's cells would take more than the scan's limit of 2,000,000 cells read, where a question counts as 1,000 cells and `HasSpill` as 4,000. The limit keeps one sheet from using up the job's time limit: a sheet that reaches it has taken 3 to 32 s. The reason then begins `its error values are spread over too many cells to list`.

`error` names the first such sheet and the summary counts `unscanned_sheets`. `timings_ms.scan` less `timings_ms.read` is the time the scan took. No test covers a picture in a cell or a linked data type such as Stocks, which need a web request, nor a what-if data table, so whether the scan lists such a cell is not known: it lists a cell where Excel's `ISERROR` is true. No test covers an Excel from before dynamic arrays either. It has no `HasSpill`, so there a typed-in error value probably ends the job with `Excel gave no answer for whether … is spilled`.

The scan replaced the `SpecialCells` listing of the releases before the last one of 12 November 2026. What a caller sees changed, and the cases that showed it through real Excel and on stand-ins, are in [references/error-scan-history.md](references/error-scan-history.md): read it when you compare a result with one from before that release, or change the scan.

`--save` keeps the copy Excel wrote. A workbook from openpyxl has no cached values until Excel or another engine saves it, so check and deliver that copy when readers need numbers without recalculating.

Office leaves four log files of each Excel session in the Windows user's temp folder, 80 MiB after a crash or a stop, and on 13 November 2026 they took C: down to 162 MB free. So once the job's Excel has ended, `scripts/office-logs.ps1` deletes that session's files and no others. `office_logs`, and `runner.office_logs` for an Excel the script had to stop, say what it deleted, and a failure is a `reason` there and in `excel.session_reason`, which fails no job. Read [references/office-logs.md](references/office-logs.md) when one of them gives a `reason` or `left` files, before you change `office-logs.ps1`, and before your own script starts Excel.

Excel runs in the user's interactive Windows session, which Microsoft doesn't support for unattended automation. The time limit and the stop of this job's own process are the guard, so run one job at a time.

Before a job, take the `windows-desktop` claim that the `work-across-tailscale-machines` skill asks for, with a note that says what the job leaves free, so that another thread does not wait on it to use the screen: `--note 'excel-com-wsl: a hidden Excel over COM; the foreground and the clipboard stay free'`.

## Prove a change to the scripts

```sh
python3 -I scripts/test_fixtures.py EVIDENCE_DIR
```

It needs `openpyxl`, builds workbooks that have each tripped this COM layer, runs them through real Excel and prints PASS or FAIL per check. `EVIDENCE_DIR` keeps each job's result as `NAME.json`, what it printed as `NAME.out` and its stderr as `NAME.stderr`, because a job that ends without a result says why on stderr only. Until 13 November 2026 the suite dropped it: one of 21 runs the day before ended at the busy case with `no job folder for busy.xlsx appeared`, an empty `busy-2.out` and no `busy-2.json`, and nothing recorded why. The `no-value` case, a job that `excel.py` turns away for a `--set` with no `=`, showed on 13 November 2026 that the message reaches `no-value.stderr`. That job starts no Excel, so since later that day the check `each job through real Excel keeps its stderr in the evidence folder` fails when such a job has no `NAME.stderr`, as a planted defect showed that the suite before missed. A full run took about 3 to 12 minutes on 12 November 2026, and a restart of the agent app cancelled such runs in the shell tool's foreground, so run each as a job of its own name, from this folder: `WSL_INTEROP=/run/WSL/1_interop agent-job start excel-fixtures-1 --env WSL_INTEROP -- python3 -I scripts/test_fixtures.py EVIDENCE_DIR`, with the interop setting that the `work-across-tailscale-machines` skill gives a unit that starts Windows programs, then `agent-job wait excel-fixtures-1 --timeout 1200` in your shell tool's background mode, with the next number for the next run. With `--no-excel` after `EVIDENCE_DIR` it runs only the cases that start no Excel, which takes under a minute and is enough while you change the error scan's handling of an answer; the full run is still the proof. Run it after any change to a script, because "a formula calculated" passes while the cases below still fail. Its busy case runs `scripts/test-busy.ps1` beside the job, which finds the job's Excel through the job's open workbook and its process ID and starts no Excel of its own. Whether that helper's rebuilds land is a matter of timing, so the case runs the job up to three times, and prints a `NOTE` line when none landed on the reopened copy. The helper's shutdown rule and the check `no job's Excel crashed`, which reads Windows' Application log for the suite's own Excel processes, are described in [references/quit-order.md](references/quit-order.md). The reads that Excel refuses are tested without Excel, by `scripts/test-read-guard.ps1`. An agent in a sandbox reaches Excel through a file queue that a runner outside the sandbox serves. Run these same cases through that queue from inside the sandbox, because a run from outside doesn't exercise the agent's route.

## Rules for your own scripts

- **Own instance, own process.** `New-Object -ComObject Excel.Application` starts a new Excel, unlike PowerPoint. Get its process ID from `GetWindowThreadProcessId($xl.Hwnd)` and write it to a file at once, because a time limit can kill the script before `Quit()`. After `Quit()` and releasing the COM objects, stop that ID alone if it lingers, checking first that the process is still `EXCEL`. `Stop-Process -Force` returns before Excel has exited, so delete the job folder or count processes only once `$p.WaitForExit(60000)` returns true, and keep the folder and report the process when it returns false. The user may be working in another Excel. An Excel that COM started has `/automation -Embedding` in its `Win32_Process` command line, `svchost.exe` as its parent and no window, while the user's has a window and no flag, as on 12 November 2026, when a probe's time limit left one running beside the user's. That tells COM's Excel from the user's, not one job's from another's, so without a recorded ID stop an Excel only when its open workbook lies in your job's folder, as `scripts/test-busy.ps1` finds the job's Excel, and leave any other running. An Excel with `/restore` on its command line is neither: Windows can restart an Excel that crashed, visible in the user's session, and Microsoft's page on `RegisterApplicationRestart` says it restarts only a program that has run for at least 60 s. On 13 November 2026 the busy case's Excel crashed in `combase.dll` at its quit after 63 s, and 8 s later Windows started such an Excel with a window and no workbook, which stayed open for hours and which no session took for a job's. Find in Windows' Application log the Excel crash just before such an Excel started, and ask the user before you close it.
- **Release the application last.** Before writing or changing COM cleanup, or investigating a crash at `Quit()`, read [references/quit-order.md](references/quit-order.md) for the object-release order and the tests behind it.
- **Delete your Excel's Office logs** once it has ended, and no other session's, as [references/office-logs.md](references/office-logs.md) says under "In a script of your own".
- **Wait for a busy Excel.** Register a message filter before the first call, as `XlCom.BusyFilter` in `scripts/excel-job.ps1` does, on a single-threaded apartment thread, which Windows PowerShell's is. A check for `RPC_E_CALL_REJECTED` around each call misses the properties that come back as `$null`.
- **Pass `CorruptLoad` by name.** Excel rejects it by position with `0x800A03EC`. Call `Workbooks.Open` through `InvokeMember` with named arguments, `[string[]]@('Filename', 'UpdateLinks', 'ReadOnly', 'IgnoreReadOnlyRecommended', 'AddToMru', 'CorruptLoad')`. Try 0 (normal), then 1 (repair), then 2 (extract data), and record which one opened it.
- **Return a range with a comma.** `return , $range`, because PowerShell unrolls a returned multi-cell range into its cells.
- **Set values through `InvokeMember`.** Several sets of different types in one job fail with "Specified cast is not valid" or "Unable to cast Int32 to String", because PowerShell's COM binder reuses the first assignment's value type at the same call site. Send whole numbers as doubles.
- **Don't wait on `CalculationState` alone.** A workbook with force full calculation on reports `xlPending` (2) for as long as it is open, although each calculate call has finished when it returns, so count 2 as done for those workbooks only.
- **Rebuild, not calculate, on a file another tool wrote.** `CalculateFullRebuild()` after opening, then `CalculateFull()` after a set.
- **Read errors by type.** `Value2` returns error cells as `Int32`, and numbers as doubles. Add 2146828288 to get the code: 2007 is `#DIV/0!`, 2042 is `#N/A`.
- **Turn off what can run or prompt.** `Visible`, `DisplayAlerts`, `ScreenUpdating`, `AskToUpdateLinks` and `EnableEvents` false, `AutomationSecurity` 3, and `UpdateLinks` 0 on open.
- **Files and output.** Copy the workbook into a Windows folder and pass Windows paths. `Set-Content -Encoding UTF8` adds a byte-order mark, so read the JSON in Python with `encoding="utf-8-sig"`.

The job is done when the results are saved outside the job folder, the job folder is gone, the Office logs of its Excel's session are gone, and the `EXCEL` process count is back to what it was before the job.
