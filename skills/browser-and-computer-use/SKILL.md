# Browser and computer use

Use only the tools named here. If you go around a rule in this skill, quote its stated reason when you report that, and ask one direct question.

## Browser

Use Vercel Labs' `agent-browser` from the shell for browser automation, verification, and web development testing on every host, in both Claude Code and Codex. Once per session, load the guide shipped with the installed CLI (`agent-browser skills get core`, adding `--full` for the command reference), and load a specialised guide from `agent-browser skills list` (such as `electron` or `dogfood`) when the task matches it. This policy governs host routing and session ownership; the CLI guide supplies commands. Follow this policy where they disagree. Run repository test suites (Playwright Test included) through the repository's documented commands.

- Use the installed Google Chrome on every host rather than Chrome for Testing, and skip `agent-browser install`. The dotfiles pull sets `executablePath` in `~/.agent-browser/config.json`; where that file or key is missing, pass `--executable-path <installed Chrome>` on `open` (for example `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"` on macOS).
- Inside a Codex workspace-write sandbox, point `AGENT_BROWSER_SOCKET_DIR`, `TMPDIR`, `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` at folders in the workspace, keep `--profile` there, and pass `--executable-path`.
- Add a random suffix to every session name (`agent-browser session id` derives the same name for every agent in one checkout), and close only the sessions you opened: `agent-browser --session <name> close`.
- Diagnose with `agent-browser doctor` without `--fix` (which removes only stale daemon socket, pid and version files, so it is safe beside other sessions); leave `--fix` to the user because it touches shared state.
- Pass `--idle-timeout <time>` on `open` when a human needs longer than the 1-hour headless idle timeout.
- When a site rejects a `HeadlessChrome` user agent, pass `--user-agent 'Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/<major>.0.0.0 Safari/537.36'` (matching the installed Chrome's major version) on every command.
- When `open` times out on a heavy page ("CDP command timed out: Page.navigate" or "no response came back"), check `get url` or a snapshot before treating `open` as failed.
- Keep launch flags (`--profile`, `--headed`, `--idle-timeout`, `--user-agent`) identical on every command (`get url`, `tab list` and `close` included) so the browser does not restart and lose sign-in. On macOS and Linux, run every command through `scripts/ab_session.py`, which saves flags once per session; on Windows, pass them on every command. Verify the user's own Chrome is not running on a profile folder before passing it to `--profile`.
- Write screenshots, PDFs, HAR files and recordings to explicit paths in a scratch directory.
- To render or screenshot a page at a set width, take screenshots with Playwright's Chromium on WSL, measure layout with `scripts/page_check.py`, test hover styles, probe page timers, or download files, read [references/page-checks.md](references/page-checks.md).
- Keep Chrome profile paths and sockets (`cua-driver serve --socket`) short (for example a `tempfile.mkdtemp()` folder under `/tmp`) so Unix socket paths stay under 108 bytes.
- Use the host's HTML preview tool (such as T3 Code's `html_preview`) only to show results to the user; inspect behaviour or layout at set widths yourself with `agent-browser` at `file://<path>`.
- After inspecting the page, run known multi-step actions in one `batch --bail` call from a scratch JSON file of argument arrays (`[["fill", "#email", "a@example.test"], ["click", "#save"], ["wait", "--text", "Saved"], ["get", "text", "#status"]]`), passed on stdin (`agent-browser --session <name> batch --bail < steps.json`, or in PowerShell `Get-Content -Raw steps.json | agent-browser --session <name> batch --bail`). End with the expected wait and state check, and keep a snapshot checkpoint whenever the next action depends on page state.
- In apps with single-key shortcuts (such as mail), target a named element inside `batch --bail` instead of page-level `keyboard type` or `press`, which hit whatever has focus after a failed click.
- On Windows, pass multiline JavaScript via `eval --stdin` because the mise and npm launchers reject or truncate newline arguments.
- Change the `agent-browser` version only through the dotfiles mise pin; if `agent-browser` prints "Daemon version mismatch detected, restarting", read [references/maintenance.md](references/maintenance.md) before signing in again.

### Profiles and sign-in

- Check `agent-browser session list` and known task profiles first, and reuse only a session this task owns. Attach to the user's own Chrome or its profile (`--auto-connect`, `--cdp`, or `--profile <profile-name>`) only with the user's approval in this task, except for the two standing exceptions below (`e-conomic-ledger-read` and paywalled news). Under the `e-conomic-ledger-read` standing exception ([incidents](references/incidents.md)), a task needing that read-only search may open or attach to the user's profile and state that it did so in the same message. When the user enables remote debugging at `chrome://inspect`, click Chrome's "Allow remote debugging?" prompt only after they approve attaching in this task and only for a connection you opened; when done, offer to turn remote debugging back off and name any other task using it.
- Read [references/attach.md](references/attach.md) before attaching to the user's running Chrome with `--auto-connect`.
- For work in the user's Windows Chrome from WSL, once they approve attaching, use `scripts/chrome-broker.mjs` instead of a DevTools client of your own: `node scripts/chrome-broker.mjs start`, `open URL [--new-context]`, and `stop` when done (`--help` lists the rest). It holds one connection, so one "Allow remote debugging?" prompt, hides secrets in every reply, and refuses fresh reads from hidden pages. First take the `windows-desktop` claim per `work-across-tailscale-machines`, and pass `start` and `open` the same `--who` (or set `CHROME_BROKER_WHO`): both exit 3 while another task's claim runs, and name it. To finish an OAuth sign-in for an account in a `--new-context` page with a session that only the user's profile holds, run `hand-over SOURCE TARGET URL-PREFIX` in the background. Once `status SOURCE` shows `watching`, press the provider's Authorize button. The command stops the redirect in the profile page and loads it in the other page, and it never prints the code.
- For sign-ins you own, keep a dedicated profile directory outside repositories and evidence, and keep cookies and tokens out of output. Because Google blocks "Sign in with Google" under automation, have the user sign in once in plain Chrome started with `--user-data-dir=<directory> --use-mock-keychain --password-store=basic --no-first-run --no-default-browser-check <url>` (`open -na "Google Chrome" --args ...` on macOS). Once the user quits Chrome, reuse it with `agent-browser --session <name> --profile <directory> open <url>`.
- Keep `--use-mock-keychain --password-store=basic` off the user's own Linux Chrome profile (its cookies live in the system keyring with `v11` values). Before starting Chrome on that profile on Linux, verify `python3 -I scripts/chrome_keyring.py check` exits 0 (a locked keyring wipes undecryptable cookies); on exit 1, give the user its unlock command. `read_page.py` and `x-browser` run this check automatically. To check sign-in without starting Chrome, copy `Default/Cookies` to a scratch path and inspect session cookie names (such as LinkedIn's `li_at`).
- Approval to use a signed-in profile covers only the sites the user named; open any other site in a dedicated profile or ask first.

### Host routing and bot walls

- When WebFetch, curl or headless `agent-browser` hits a 403, Cloudflare check or bot wall on a read-only page, read [references/bot-walls.md](references/bot-walls.md). On WSL, try a `--headed` session on hidden display `:99` first without asking: `env -u WAYLAND_DISPLAY DISPLAY=:99 scripts/ab_session.py start NAME --headed -- open URL`. Ask before opening a visible `--headed` window on the user's desktop. If the page still fails (or for a PDF a deliverable will quote), offer to read it in the user's own Chrome with `scripts/read_page.py` before falling back to an abstract or summary, and report any unread source facts explicitly.
- Fetch public X/Twitter posts and long articles without a browser via `curl -s https://api.fxtwitter.com/status/<id>` (long article text is under `tweet.article.content.blocks`); check `code == 200` and fall back to `agent-browser` if it is down.
- Read paywalled news sites (such as the FT and The New York Times) through the user's own Chrome profile and `cua-driver`'s accessibility tree without asking first (the second standing exception alongside `e-conomic-ledger-read`). Keep DevTools (`browser_prepare` or `agent-browser`) off this profile so bot checks do not block it.
- Read [references/read-page.md](references/read-page.md) before running `scripts/read_page.py`. Avoid `cua-driver launch_app` with `urls` on the user's Chrome (it injects a tab into their front window). When a profile holds several accounts for one app, pass an account hint (such as `https://outlook.office.com/mail/?login_hint=<address>`) and assert the signed-in address on the page before searching or capturing.
- `agent-browser` runs on the command's host (`localhost` reaches that host's dev servers; Windows Chrome also reaches WSL dev servers on `127.0.0.1` via mirrored networking). On WSL, Windows Chrome and WSL Chrome have separate networks and profiles: if Windows Chrome returns nothing, test Windows TCP connectivity first (`powershell.exe -NoProfile -Command '(Test-NetConnection example.com -Port 443).TcpTestSucceeded'`, avoiding `curl.exe` or `Invoke-WebRequest` so endpoint security does not isolate Windows), then try `--headed` on WSL `:99` before reporting a block. Inform the user before switching hosts or profiles.
- To share a local dev server with another host, reuse a task-owned tailnet share or run `tailscale serve <port>` in the foreground, recording its PID and URL; stop only that PID when done and confirm the URL no longer loads (a foreground share is absent from `tailscale serve status`). For persistent shares (such as for the user's phone), follow `work-across-tailscale-machines`.
- Codex's in-app browser (`iab`) exists only inside the Codex desktop app.
- On Windows, read [references/windows.md](references/windows.md) before starting an `agent-browser` session (native shell or SSH).
- To drive an Electron app or a task-started Chrome with remote debugging, read [references/cdp.md](references/cdp.md).

## Computer use

Prefer a CLI, API, or browser tool when it can do the job. Use desktop control only for native apps and reading pages in the user's own Chrome. When a value exists only in an app window, or you would otherwise give click steps, drive the app yourself (including cleanup of tools you installed). Before claiming a product lacks a control or is unreachable, check its other interfaces (desktop app, config file, local install, Windows-side driver) and name the ones you checked. For a consent or permission prompt inside an approved action, state what it grants, offer in the same message to click it, and act on the user's yes. Before asking the user to paste mail or chat content, offer to read it in the app and wait for their yes. If an app you started in its own `dbus-run-session` exposes no accessibility tree, enable accessibility on that bus (`org.a11y.Status` `IsEnabled`, `ACCESSIBILITY_ENABLED=1`) and run `cua-driver` with the same `DBUS_SESSION_BUS_ADDRESS`.

Before driving a native app with `cua-driver`, reading a WSLg window on `:0`, sending keys or pasting into a Windows or Electron app, or polling windows in a loop, read [references/computer-use.md](references/computer-use.md).
