# `cua-driver` on macOS and Windows

On macOS and Windows, use `cua-driver` through its CLI, or its MCP tools when connected, for Codex and Claude Code alike. Read its own `cua-driver` skill first. Check `cua-driver status` and `cua-driver doctor` before driving an app, then discover the exact app and window with the driver's tools. Use `cua-driver call <tool>` with JSON on standard input for CLI calls. For a `run_script` flow, write the script to a file and run `node scripts/cua-js.mjs <file>`, which prints only its console output and return value, or its error with the script line; `--calls` adds the per-call log. Pass one named `session` on every call of a flow that acts on an element token from an earlier call, because a token belongs to the session that read it, and a call without one runs in a throwaway session that refuses the token as stale. Otherwise leave `--session` out, because a named session expires after five idle minutes. An expired label rejects every call, reads included, with exit 1, empty stdout and the reason on stderr, so read stderr and carry on under a new label.

If the daemon is stopped, start the installed one. On macOS run `cua-driver permissions grant`, which launches the installed CuaDriver app by its exact path, so the daemon runs under that app's own Accessibility and Screen Recording grants. If it waits on a macOS prompt, ask the user to approve it. On Windows run `cua-driver autostart kick`.

Chrome's Save As dialog on Windows is a separate top-level window with its own PID, so send `press_key` `return` to that window, then confirm the file on disk, because the effect reports as unverifiable.
