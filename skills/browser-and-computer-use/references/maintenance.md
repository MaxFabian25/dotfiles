# Maintenance

## Versions, upgrades and updates

Tool versions live in `config/mise/config.toml`; host-specific integrations stay in the private configuration. Every host runs the installed Google Chrome through `executablePath` in `~/.agent-browser/config.json`. The dotfiles pull manages only that key, chosen from Google's install paths in `config/agent-browser/chrome.toml`, and blocks on a host without Google Chrome. Leave existing Chrome for Testing downloads in place, because other sessions may still use them. Before upgrading agent-browser, finish or hand back all live sessions. Afterwards, run `agent-browser doctor --offline --quick` on each host and reread `agent-browser skills get core` for changed guidance. On Linux, after an agent-browser or Chrome upgrade and after a change to `scripts/ab_session.py` or `scripts/approve_attach.py`, also run `python3 scripts/attach_selftest.py`. It attaches five times to a throwaway Chrome profile of its own, which opens a Chrome window on the desktop for about a minute, and exits 0 when every attach worked. The scripts' unit tests run against stand-ins, so only this shows that a new Chrome or agent-browser still behaves as they expect. Recheck the Windows download workaround when a release fixes #1659. Preserve native computer-use integrations independently of browser updates. Update cua-driver by the steps under Updating in `config/cua-driver/README.md` in the private dotfiles repository, and never run `cua-driver update --apply` or the vendor's install script directly on WSL or Windows. As read in the vendor's install scripts on 10 November 2026, they stop every running `cua-driver` process on the machine, which cuts the driver connection of other agent sessions, and on Windows they download with PowerShell web cmdlets, which the user's rules forbid on that PC.

## Measuring a CLI workflow change

To measure a CLI workflow change, run `python3 <skill-dir>/benchmarks/benchmark.py --output <new-scratch-directory>`. The [probe](../benchmarks/benchmark.py) uses a synthetic local form, five interleaved trials per workflow, exact saved-state checks, and owned-session teardown. Its results cover that local flow and CLI bytes only. Keep the CLI's default waits; tune a slower task from its own evidence.

## Daemon version mismatch

- "Daemon version mismatch detected, restarting" means two agent-browser versions drove one session. The restart closes its pages and drops every sign-in kept only for that browser session, such as a login held in a session cookie, with no error on the page. An agent shell started before an upgrade keeps the old CLI first on its `PATH`, so before signing in again, compare `agent-browser --version` across each launcher the task uses, such as the shell, PowerShell and Python's `shutil.which`, and call one binary by its path, such as the mise shim.
